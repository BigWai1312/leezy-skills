# LEEZY DOCX

> LEEZY Skills · 作者 [BigWai1312](https://github.com/BigWai1312) · [技能源地址](https://github.com/BigWai1312/leezy-skills/tree/main/skills/leezy-docx) · MIT License，见 [LICENSE](LICENSE) 和 [NOTICE.md](NOTICE.md)。

中文说明：Markdown 优先、样式驱动的 Word 报告排版。安装、输入要求及示例见 [README.md](README.md)。本技能提供工作规范，不内置一键转换器或 Word 插件；生成与渲染需要执行环境及文档工具。署名仅用于技能，不自动写入用户报告或将其改为作者作品。

为中文技术报告维护清晰的 Markdown 源稿和可通过 Word 样式统一修改的 DOCX。核心交付是可维护的排版结构，不只是当次看起来一致。

## 判断当前任务

- 用户只要求修改 Markdown 时，直接修改已确定的源稿，检查图片链接、图表编号和正文引用；不要顺带生成或修改 DOCX。
- 用户要求制作 Word 或明确包含排版交付时，先完成源稿中的相关修改，再生成 Word，无须重复索取已经明确的授权。
- 仅调整已有 Word 的样式时，可直接在副本中修改样式，无须强行重建 Markdown。保留用户在 Word 中添加的内容、批注、域和书签。
- 用户仅要求创建或修改本技能时，只改技能文件，不自动改报告。
- 不凭文件时间认定权威稿。优先采用用户指定文件，其次检查项目记录中的权威源稿路径；多个候选仍有实质歧义时再询问。
- 不把旧报告的地图或分析文字作为新报告成果。核对实际来源、指标年度、单位和统计口径，不以排版修改替代数据核验。

## 样式是格式的唯一主入口

生成或调整 DOCX 前，阅读 [references/style-contract.md](references/style-contract.md)。其中规定样式名称、默认参数、继承关系和检查要求。

1. 先定义样式，再生成内容。正文、标题、图题、表题、表内文字、图片段落、公式、列表、页眉页脚等使用相应的“修改的XXX”样式。
2. 同类内容的字体、字号、颜色、段距、行距、缩进、对齐、分页控制都写在样式里。不要在每个段落或 run 上重复赋值。
3. 直接格式仅用于必要的局部例外，并记录理由。强调、变量等优先使用字符样式；不要清除数学公式、上下标、超链接、修订或域的结构属性。
4. 已有同名样式时复用。用户已修改的样式是继续编辑时的依据，不在每次生成或更新中重置成默认值。
5. 正文中文宋体五号，英文和数字 Times New Roman，首行缩进 2 字；其他默认参数见样式契约。明确的用户要求或选定模板优先。
6. 样式应可在 Word 样式窗格找到；关闭样式“自动更新”，避免单段手工修改反过来污染全篇。
7. 不将图片内文字、纸张边距、表格列宽或图片尺寸谎称为段落样式可统一控制。它们分别由出图源文件、节设置、表格布局和图片对象管理。

## 章节与自动编号

- 使用真实标题层级和多级列表。自定义“修改的一级标题”等仍须保持大纲级别、目录识别、章节编号和 `STYLEREF` 的一致性。
- 图、表、独立公式使用章节号与 `SEQ` 域；正文引用使用书签与 `REF` 域，页码引用使用 `PAGEREF` 域。避免“看起来是编号”的静态文本。
- 编号只能由一处产生，避免手打章节号与列表号重复。附录采用独立编号序列，并验证其题注不会串入正文章节。
- 不对含域或书签的整段赋 `paragraph.text`，不将域转换成静态结果。
- 目录和题注的内置样式可能在 Word 更新时重新应用。保留必要的内置 styleId，采用契约中的继承或映射方式，更新域后重新检查。

## 目录排版

- 报告默认包含可更新的自动目录。“目录”两个字使用“修改的目录标题”：黑体小二（18 pt）、居中。
- 目录一级条目使用“修改的目录1”：黑体四号（14 pt）；二级及以下使用“修改的目录2”“修改的目录3”等：宋体小四（12 pt）。这些设置只针对目录，不改变正文标题格式。
- 目录标题与条目均为单倍行距；条目段前段后为 0。一级条目左缩进为 0，二级起每级默认增加 0.74 cm，全部取消首行缩进。
- 所有目录页码在同一版心右边界右对齐，通过右对齐制表位和点引导符实现，不用空格或手打点线。较长标题自然换行，留出页码空间。
- 目录标题本身不进入目录；默认收录一至三级，用户指定其他层级时按相同规则扩展。更新整个目录后检查字体、字号、单倍行距、递增缩进与页码对齐仍然有效。

## 图表、公式与页面

- 图片等比缩放至版心以内；图片段落使用“修改的图片”，图题使用“修改的图题”，图注使用“修改的图注”。图片与图题保持同页，避免把大段分析也串成不可拆分页块。
- 表题在表上、图题在图下。表格使用黑色三线表，透明底色（无填充），不加彩色表头、隔行底色、竖线或逐行网格。
- 表头用“修改的表头”：黑体；表内用“修改的表格”：宋体。两者是独立段落样式，字号默认均为小五（9 pt），不能只靠直接加粗区分。
- 表头上方顶线与表格底线均为粗实线，默认 1.5 pt；完整表头下方分隔线为细实线，默认 0.75 pt。统一由“修改的三线表”及其条件格式管理。
- 跨页时每个续页表格上方显示“续表××”（如“续表5-3”），重复完整表头；每页表格片段都有相同的粗顶线、细表头线和粗底线。续表号引用原表号，不新增 SEQ 编号。详细实施与分页核验见样式契约。
- 表格外观用表格样式，单元格文字用段落样式。不要用固定行高压住内容；列宽按内容与版心设置，宽附表必要时使用横向节。
- 数学公式用原生可编辑 OMML；保留上下标、分式、矩阵等结构。检查行内公式基线、独立公式编号和表内公式，不将 LaTeX 字符串或图片冒称 Word 原生公式。
- 无其他模板约束时采用 A4，上下边距 2.54 cm、左右 3.18 cm；封面不显示页码，目录罗马页码，正文阿拉伯页码，附录续正文页码。保留真实封面日期，不以当前日期自动替换。

## 实施与核验

- 优先复用任务现有生成器和模板，仅修改本任务涉及部分；不要直接复制含硬编码报告路径、题名、章数和数据的旧脚本作为通用生成器。
- 可用 `python-docx` 与 OOXML 生成和审计。需要文档运行时或渲染器时，通过当前可用的工作区依赖工具定位，不把某次安装路径写死。
- 在 Word 等可用渲染环境更新目录、正文及页眉页脚域并重新分页；前向引用必要时再次更新。不在收尾阶段对全文 `.Font` 或 `.ParagraphFormat` 赋值，这会形成压过样式的直接格式。
- 新建生成流程至少用一份隔离小样检验：正文、两级标题、图、跨页表、公式、目录和交叉引用。不要用正式报告试验破坏性更改。
- 对新增和修改内容检查样式覆盖率及直接格式；在小样中只改“修改的正文”字号和行距，确认正文跟随且题注、表格不受影响。插入一个题注后更新域，确认编号和引用同步。
- 渲染实际交付 DOCX，检查图片、图题、跨页表、公式、目录与页眉页脚。不能渲染时明确说明检查限制，不把 XML 检查称为版式检查。
- 交付时简要指出主要样式以及“在 Word 样式窗格修改对应样式”的使用方式。仅交付用户要求的格式，不把内部 PDF、截图或测试文件作为正式成果。
